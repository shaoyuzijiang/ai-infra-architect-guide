# 决策速查表（选型判断依据）

每张表对应课程里的一组受控对照。现场用：先定位问题，再按表选路，并记住每条路的边界。

## 表 A · 显存不够放 KV 了（推理，ch05–15 依序升级）

| 手段 | 机制 | 代价 | 边界 |
|---|---|---|---|
| 管住并发/预算 | Token Budget 控制同时运行的请求量（ch06） | 吞吐下降，排队变长 | 治本是准入控制，治标是限流 [业界通识] |
| Paged 化 | 逻辑序列→物理 Block，消灭预留浪费（ch05） | 块表管理开销；教学实现无 fused kernel | 生产需 fused PagedAttention [业界通识] |
| 共享前缀 | 相同 system prompt/前缀只算一次（ch08） | 只共享填满且不可变块 | 多轮对话/同系统提示词场景收益大 |
| 整请求换出 CPU | swap：KV 完整保留，断点续算（ch12） | PCIe 传输时间，恢复路径长 | 传输时间可被服务级 SLA 吸收时用 |
| 丢弃重算 | recompute：丢 KV，恢复时重新 Prefill（ch12） | 重算算力 | 短请求/低恢复价值时更划算 |
| 异步分层搬运 | 独立 Copy Stream + Event，传输与计算重叠（ch13） | 实现复杂度 | 教学实现为同步对照基准 |
| 外部 Cache 进程间复用 | 跨引擎复用已有 Prompt KV（ch14） | 至少重算最后一个 Prompt Token；跨进程生命周期管理 | 多实例/多会话复用 system prompt 场景 |
| PD 分离 | Prefill/Decode 不同 Worker，各自扩缩容（ch15） | KV 传输与首 Token 跨机 | 大规模集群才值得上 |

## 表 B · 训练显存不够（训练状态切分，ch29–42）

| 手段 | 切什么 | 省下的显存 | 多付的通信 | 什么时候用 |
|---|---|---|---|---|
| DDP（ch29） | 不切，纯复制 | — | 一次全量梯度 AllReduce | 卡够放全套状态 |
| ZeRO-1（ch32） | 优化器状态 | 12N/W → 3N/W（状态部分） | 更新后参数 AllGather | 第一步切分，通信代价最小 |
| ZeRO-2（ch33） | +梯度 | Reduce-Scatter 只留本 Rank 分片 | 与 AllReduce 同量级 | 再省一档 |
| ZeRO-3/FSDP（ch34） | +参数 | 三者都分片常驻 | Forward/Backward 前 AllGather | 单卡放不下参数时 |
| TP（ch35–38） | 层内权重/激活 | 单层太大时 | 每层高频通信，须高速互联 | 层内矩阵大到单卡算不动 |
| PP（ch39–41） | 按层跨卡 | 层数÷卡数 | 只传边界激活 | 层间串行依赖天然成流水 |
| 三维组合（ch42） | DP×TP×PP | — | — | 集群规模定型后的标准做法 |

> 显存账的写法（售前口径）：状态 ≈ 16 字节/参数（FP32+AdamW）；ZeRO-W 卡后常驻 ≈ 16N/W 量级——用相对关系讲，不要背具体 GB，现场代入算。

## 表 C · 单卡每步太慢（训练步体，ch23–28 依序叠加）

| 手段 | 动哪一段 | 不动什么 | 风险 |
|---|---|---|---|
| BF16 混合精度（ch23） | Forward/Loss 精度 | 主参数/梯度/优化器状态仍 FP32 | bf16 动态范围大，无需 loss scale |
| 梯度累积（ch24） | 一个 step 拆 K 个微批 | 梯度数学等价（loss 缩放加权） | 加权规则错了梯度口径就错 |
| 重算激活（ch25） | 反向时的激活供给 | — | 多一遍前向计算 |
| FlashAttention（ch26） | Attention kernel | 数学不变 | 训练版需带 backward |
| Fused/foreach 优化器（ch27） | 更新 kernel 组织 | AdamW 数学不变 | 收益在 kernel 发起次数 |
| torch.compile（ch28） | 图编译执行 | 语义不变 | 首次编译成本、变长重编译 |

## 表 D · 两条"要不要上"的判断

| 问题 | 判断依据 |
|---|---|
| 要不要上 Speculative Decoding（ch11） | 解码目标与 draft 模型是否同分布族、接受率够不够高；greedy 下输出不变，收益=省 Target 串行步数 |
| 要不要上 PD 分离（ch15） | Prefill/Decode 负载比例失衡、集群规模大到分开扩缩容有收益；小规模分离纯属复杂度 |
