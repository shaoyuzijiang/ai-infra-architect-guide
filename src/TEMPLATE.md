# 教案模板（TEMPLATE）

> 每章教案 vs 原版（README「一个变量+受控对照实验」）的分工：原版回答"这个优化在受控条件下值多少"；教案回答"它是什么、为什么存在、在产品里长什么样、在方案里什么时候用、怎么讲给外行、学完你会什么"。教案不复制原版，只短引用（≤25 字/处）并注明出处。

## 每章 10 个字段（顺序固定）

1. **一句话定位**：这章的机制是什么，20 字内。
2. **解决什么问题**：不用术语开头，用场景/痛点语言（"上万人同时用…时…会…"）。1–2 句。
3. **原理图解**：`<!--fig:chNN-->` 占位符，构建时内联 SVG（规范见下）。
4. **原理要点**：3–5 条 bullet。每条一句、只讲一个机制事实；关键公式/数字直接给出（必须与 README/教材一致）。baseline 与 variant 的对比写在第一条里。
5. **重点**：合上书唯一要背的一句话（粗体）。
6. **边界与常见误区**：1–3 条。第 1 条必来自 README「已知边界」最重要的那条；可加一条 `[易错]` 标注的常见误解及其纠正。
7. **产品对应**：具体产品名 + 模块名（如 vLLM 的 `PagedAttention`、SGLang 的 `RadixAttention`、FSDP、DeepSpeed ZeRO、Megatron-LM、LMCache、TensorRT-LLM）。README 提到的直接写；README 没提的标 `[业界通识]`。
8. **方案视角**：什么时候客户/业务需要它、什么时候不需要、判据是什么（能落到"看哪个指标/问哪个问题"）。2–3 句。
9. **讲给客户的一句话**：可直接用于售前/汇报，不夸大、不带绝对化（避免"一定/彻底/无限"）。
10. **掌握目标**：1–2 条可验证行为，动词限定为：画出/算出/答出/判断/区分。示例：「能画出 KV Block 的逻辑→物理映射」「能算出 7B 模型 FP32+AdamW 的常驻显存」。

末行 **深挖入口**：`帖子「帖名」（日期）· 教材 pNN · 仓库 chapter_NN`（训练篇无教材页；ch30–43 写"帖子未发，读仓库"）。

## 原理图解 SVG 规范（每章一张，机械可执行）

- 画布 `viewBox="0 0 760 H"`，H 取 180–300。内容结构固定为上下两行：
  - 上行 = **baseline**（原版对照路径）：灰调。
  - 下行 = **variant**（本期机制）：强调调。
  - 左端各放行标签（`baseline` / `variant`），右端各放结果标签（如"每步重算全部历史" / "每步只算新 Token"）。
  - 变量发生的位置用 `stroke: var(--warning)` + 虚线框或加粗箭头标出。
- 只允许这几种元素：`rect`（圆角 6）、`text`（.lbl 12.5px 主文字 / .sub 10.5px 灰字 / .tag 10.5px 强调字）、`path` 箭头（marker-end）。
- 颜色只用主题变量：`--fg --muted --border --surface --accent --warning`（站内 CSS 变量，暗色自动适配）。
- 文案规则：每框 ≤10 字；箭头上可放 1 个 ≤8 字的小字；总文字 ≤90 字。
- 首元素带 `role="img"` 和 `aria-label="chNN 原理图解：<主题>"`。
- 存为 `src/fig/chNN.svg`，md 里用 `<!--fig:chNN-->` 引用（构建时内联）。
- 允许的框内小字用 `font-family` 继承页面；不需要 `<style>` 以外的任何外部资源。

## 质量红线

- 一切机制事实、数字、边界以 `chapter_NN/README.md` 为准；教材（PDF 对应页）可用来补理论表述，但数字以 README 实测为准。
- 不虚构 benchmark；不确定的业界事实一律标 `[业界通识]` 或不写。
- 每章正文（除图解）≈ 500–650 汉字；不写废话过渡句。
