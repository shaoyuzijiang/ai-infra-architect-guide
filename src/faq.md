# 售前 / 答辩 FAQ（机制版答案）

每条答案都是"机制一句话 + 出处章"。背下来不够，要能现场展开一层。

**Q1 · 客户：模型 7B，一张 80GB 卡跑训练够吗？**
机制版：常驻状态 ≈ 16 字节/参数（FP32 参数+梯度+AdamW 两状态）≈ 112GB，没算激活——单卡不可能。要么 ZeRO 切分到多卡（ch32–34），要么换 bf16 纯推理思路。追问点：客户说的"训练"是全参数 SFT 还是 LoRA/推理？三者差一个数量级。

**Q2 · 客户：为什么上下文越长，每次回答越慢越贵？**
机制版：KV Cache 随上下文线性涨（公式二），Decode 每步都要读全量 KV；Prefill 一次算完整个 prompt（ch02 已知边界：Decode 并非与上下文长度无关的常数复杂度）。长上下文贵在 KV 存储+带宽，不在"思考更久"。

**Q3 · 客户：都说 PagedAttention 省显存，到底省在哪？**
机制版：固定批/连续批时代 KV 按"全局最长请求"预留 dense 空间，短请求的空槽全是浪费；Paged 把逻辑序列映射到固定大小物理块，按需分配释放（ch05）。省的是"预留但不填"的部分。注意边界：教学实现无 fused kernel，生产引擎另有 kernel 优化 [业界通识]。

**Q4 · 客户：多轮对话/固定 system prompt，重复算不浪费？**
机制版：前缀相同 → 前缀 KV 可共享（ch08）。只共享"填满且不可变"的块，所以不用 CoW；至少重算最后一个 prompt token（KV 不存首 token 的 logits）。

**Q5 · 客户：GPU 都满了，新请求进来怎么办？**
机制版：准入控制（预算/排队，ch06）→ 不够时抢占：swap 保留断点 vs 重算放弃缓存（ch12，取舍是 PCIe 时间 vs 重算算力）→ 更大规模上外部分层缓存与 PD 分离（ch13–15）。

**Q6 · 领导：为什么大厂要做 PD 分离？我们用得上吗？**
机制版：Prefill 是"一次吃长序列"，Decode 是"每步走一小步"，资源形状完全不同；同一 Worker 里互相干扰（ch15）。规模大、两类负载比例失衡才值得分离；小规模上了就是纯复杂度。

**Q7 · 客户：agent 应用怎么容量规划？**
机制版：先问请求形态。agent 循环式（多轮工具调用、长驻上下文）的 KV/存储消耗是聊天式的百倍量级（原作者 8/10 帖结论性观察：数百倍内存消耗）——按"并发数×上下文长度×驻留时长"算，不按"日活"算。

**Q8 · 客户：国产卡/ASIC 能不能替换 NVIDIA？**
机制版：看生态三件套——CUDA 生态的 kernel 覆盖（如 FlashAttention 类算子）、通信库（NCCL 对应物）、推理引擎适配。训练侧要求更高（并行通信栈）。延伸：原作者《廉价算力的希望——ASIC芯片》《国产算力，终于要上桌吃饭了》《求寒武纪显卡推理性能》等帖（延伸阅读）。

**Q9 · 领导：训练中断了怎么办，之前白跑了？**
机制版：取决于 checkpoint 覆盖度。完整训练状态=参数+优化器状态+调度器状态（warm-up 进度等，ch43）；分片保存+manifest 恢复语义最完整。没保存调度器状态的"能续"大多是假续。

**Q10 · 客户：为什么你们的方案不用更大的单卡就行？**
机制版：因为三座大山（参数/梯度/优化器状态）+ KV 都吃显存，大卡只是把爆炸点推迟；ZeRO/TP/PP 是结构性解法，不是权宜（表 B）。反过来也要会讲：能单卡/少卡解决的，不上分布式——通信是真实的税。

**Q11 · 面试/答辩：KV Cache 为什么有时候开了更慢？**
机制版：小模型+短上下文时，省下的计算量小于 Cache 管理开销（拼接/调度/kernel 发起）（ch02 实测：16-token 负优化，1024-token 才 1.85×）。能答出"优化有适用边界"比背加速比高一个档次。

**Q12 · 面试/答辩：梯度累积和加大 batch 是一回事吗？**
机制版：等价的前提是 loss 缩放口径正确（微批 i 按 token_sum_i/total_supervised 加权，ch24）。梯度数学等价、优化器视角一样；但 BatchNorm 类统计、性能特征不同。Qwen3 用 RMSNorm，无此坑，但回答要显式提边界。

**Q13 · 面试/答辩：ZeRO-1/2/3 一句话区分？**
机制版：切优化器状态 → 再切梯度 → 连参数也切（ch32–34）。代价依次是参数 AllGather、Reduce-Scatter、双向 AllGather；通信越多，换来的是常驻显存 16N/W 量级递减。

**Q14 · 面试/答辩：TP 和 PP 通信量谁大？**
机制版：TP 每层都要通信（前反向高频、要求高速互联）；PP 只在 stage 边界传激活（量小但引入 bubble）。所以 TP 卡要同机高带宽，PP 可以跨机（ch35–41 的架构含义）。
